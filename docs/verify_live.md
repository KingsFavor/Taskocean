# 실계정 라이브 검증 가이드 (TaskOcean)

앱에서 직접 동작을 수행하고 **Google Tasks 웹**(tasks.google.com, 또는 Gmail/Calendar 우측
사이드바)에서 서버 상태를 대조한다. 대부분 "앱에서 변경 → 웹에서 확인 → (반대로) 웹에서 변경
→ 앱에서 확인" 왕복으로 검증한다.

## 사전 지식 (결과 해석용)
- **서버→앱 반영은 폴링(약 90초)** 이다. 즉시 보려면 앱을 다른 앱으로 전환했다가 다시
  TaskOcean으로 돌아오면 된다(마지막 폴링 후 30초 지났으면 즉시 당겨옴).
- **마감일(due)은 날짜 단위만**. 시간은 없다.
- **완료 타임스탬프는 서버가 채운다**(앱은 `status`만 보냄). ← 이미 실측 확정.
- **계정 간 이동은 재생성+삭제**다. 대상 계정에 **새 id로 다시 생성**되고 원본은 삭제된다
  (완료/위치/생성일 이력은 초기화됨 — 정상).
- **리오더는 같은 리스트/계정 안에서만**.
- 낙관적 UI라 앱에는 즉시 반영되고, 잠시 뒤 서버 반영 점(동기화 표시)이 사라진다.

---

## 1. 완료 / 해제  ✅(이미 실측됨, 재확인용)
1. 아무 태스크나 체크 → 앱에서 취소선.
2. Google Tasks 웹에서 같은 태스크가 **완료** 상태인지 확인.
3. 다시 체크 해제 → 웹에서도 미완료로 돌아오는지 확인.

## 2. 하위작업 — 부모 리스트 이동 시 함께 이동  ⬅ 최우선 미검증
> 같은 계정 안에서 부모 태스크의 리스트를 바꾸면 하위작업도 따라와야 한다.
1. 리스트 A에 부모 태스크 생성(예: "이동테스트").
2. 그 카드를 펼쳐 하위작업 1개 추가(예: "자식1").
3. 카드를 더블클릭 → 편집 모달 → **리스트를 B로 변경**(같은 계정) → 저장.
4. **기대:** 부모와 자식이 **둘 다 리스트 B**로 이동, 자식은 여전히 부모 밑.
5. **확인:** 앱에서 B 리스트로 필터해 부모+자식 확인, Google Tasks 웹에서도 B에 둘 다 있는지.
6. 정리: 부모 삭제(자식도 함께 삭제되는지 = cascade 확인 겸).

## 3. 계정 간 이동 (재생성+삭제)
1. 태스크(하위작업 있으면 더 좋음) 우클릭 → "다른 계정으로 이동" → 대상 계정의 리스트 선택.
2. **기대:** 원본 계정에서 사라지고, 대상 계정 리스트에 (하위작업 포함) 새로 생김.
3. **확인:** 웹에서 원본 계정엔 없고 대상 계정엔 있는지. 대상 태스크는 **새 항목**이다.

## 4. 추가 / 마감일 / 메모 / 리오더
- **추가+마감일:** 퀵캡처로 "회의 준비 내일" 같은 식으로 추가 → 웹에서 제목과 **날짜**(내일)
  맞는지. (시간은 안 붙는 게 정상.)
- **메모:** 편집에서 메모 입력·저장 → 웹에서 메모 확인. 지웠을 때 웹에서도 비는지.
- **리오더:** 같은 리스트에서 드래그로 순서 변경 → 앱 재실행(또는 90초 폴링) 후에도 순서
  유지되는지. (다른 계정/리스트로의 드래그는 지원 안 함이 정상.)

## 5. 삭제 cascade
- 하위작업 있는 부모 삭제 → 웹에서 부모+자식 모두 사라지는지.

## 6. 완료 정리 (clearCompleted)
- 몇 개 완료 → 리스트 메뉴의 "완료 정리" → 웹에서 완료 항목들이 숨겨지는지(삭제가 아니라
  hidden 처리 — 웹에서 "완료된 항목 표시"로 복구 가능).

## 7. 재인증 배너 — **7일 안 기다리고 강제 테스트하는 법**  ⬅ 추천
Testing 모드 refresh 토큰은 7일 뒤 만료되지만, **지금 강제로** 만료 상황을 만들 수 있다:
1. https://myaccount.google.com/connections (또는 보안 → 타사 앱/서비스) 접속.
2. **TaskOcean(또는 해당 OAuth 앱)** 의 액세스 **삭제/해제**.
3. 앱으로 돌아와 아무 동작(완료 토글 등)을 하거나 폴링(~90초)을 기다린다.
4. **기대:** 그 계정만 `재로그인 필요` 배너 표시(다른 계정은 정상 동작 = 계정 격리 §8.7).
5. 배너의 **다시 로그인** 클릭 → 스피너 "로그인 중…" → OAuth 창 → 같은 계정으로 로그인 →
   배너 사라지고 대기 중이던 변경이 반영되는지.
6. **주의:** 재로그인 시 반드시 **같은 Google 계정**을 선택해야 복구된다(다른 계정 선택 시
   배너 유지 — 의도된 동작).

## 8. 멀티 계정 격리
- 7번을 한 계정에만 적용 → 그 계정만 배너, 나머지 계정 태스크는 계속 보이고 조작 가능한지.

## 9. 오프라인 → 복귀 (outbox 내구성)
1. Wi-Fi 끄기.
2. 태스크 완료/추가/편집 몇 개(앱엔 즉시 반영, 동기화 점 표시).
3. **앱 완전 종료** 후 Wi-Fi 켜고 재실행.
4. **기대:** 종료 전 변경들이 서버에 반영(웹에서 확인). 디스크 outbox가 재실행에도 살아남아
   순서대로 flush.

## 10. 서버 → 앱 (폴링)
- Google Tasks 웹에서 태스크 추가/완료/수정 → TaskOcean으로 전환(또는 90초 대기) →
  앱에 반영되는지. (단, 앱에서 대기 중인 변경이 있는 항목은 그 변경이 우선.)

---

### 문제 발견 시
증상(무엇을/어떤 순서로 했고 앱·웹이 각각 어떻게 보였는지)만 알려주면 재현·수정한다.
깊은 진단이 필요하면 `GoogleTasksAPI.perform`에 임시 HTTP 로깅을 다시 붙여
(터미널 실행 + 콘솔) 요청/응답을 직접 볼 수 있다.
